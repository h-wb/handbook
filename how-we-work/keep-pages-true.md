# How pages stay true

## Two dates, two meanings

- **Last changed** is kept by git. It says someone touched the page.
- **`reviewed`** is set by hand. It says someone checked the page against
  reality and it was true that day.

An edit never changes `reviewed`. Only a check does.

## When a page is due

A page is due when today minus `reviewed` is more than its interval.

| Type | Interval |
| --- | --- |
| how-to | 90 days |
| overview, reference | 180 days |
| plan | 30 days |
| decision | never: it is superseded, not reviewed |

`review_every` in a page's header overrides the default.

## Where you see it

[INDEX.md](../INDEX.md) lists every page of every repo in the registry with its
status, its last review and whether it is due, the longest-unreviewed first.
It is generated by `tools/build_index.py`; nobody edits it.

## Who checks, and when

- **With the work.** A task is not done until the pages it made wrong are fixed.
- **Once a week.** An agent takes the five pages longest without review, checks
  each against the code or the cluster, and either sets `reviewed` or fixes the page.
- **You** are asked only when a page states something only you know.

## What happens to a page that is wrong

| Finding | Action |
| --- | --- |
| Still true | Set `reviewed` |
| Partly wrong | Fix it, set `reviewed` |
| Replaced by another page | `status: superseded`, `superseded_by` the new page |
| About something that no longer exists | `status: archived` |

Nothing is deleted: an archived page keeps its id, so old links still resolve.
